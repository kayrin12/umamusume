# 赛马娘繁中服 · 养成助手 v0.7

Windows 10/11 64位只读辅助：读取可见游戏画面，常规训练使用本地OCR和经验规则，事件/心得等使用 ChatGPT 账号（官方 Codex）或视觉 API，独立记录每次养成。不自动点击、不读游戏内存、不修改游戏文件。

**这是可测试原型。攻略含跨服推定和作者经验，缺少完整评分模型；不保证每回合最优或达到 UB。** 用户已确认旧版可捕获窗口；v0.7 的真实 Windows OCR、游戏识别和账号分析仍需本机验收。

## v0.7：默认自动读取，无需采样

**日常只需选游戏窗口，点“开始自动辅助”，然后自己在游戏里浏览训练。** 无需先采0–9、框选六个字段、选择五个模板、填写权重或登录模型。已有v0.6设置也会在点击该按钮时切换到自动模式。以下v0.6手工模板工具已折叠到高级设置，供可选纠错使用。

程序首次用Windows本机OCR获取文字和位置，自动寻找日期、选中的训练、六列收益、失败率。定位成功后保存相对坐标至 `local-data/auto-layout.json`，只OCR变化区域；不变字段复用结果，角色动画在区域外时不会重跑OCR。定位失效或收益未读全会自动重试，不要求用户完成模板库。没有增加运行环境、第三方图像或大型模型。

常规训练建议完全本地计算，每看到一个完整预览就缓存并重排，五项齐后给具体行动。没有进行中的局次时，一键开始会在识别到训练画面后自动建立记录；跨回合清空训练缓存。重启遗留的局次、日期倒退、疑似放弃重开仍须确认归属，避免自动混局。

识别零收益需先定位完整六列收益行，再检查对应格子没有文字前景；识别失败的可见数字会保持未知。选中训练优先读唯一训练标题，否则只接受唯一明显的黄色高亮标签；不能把五个按钮都可见当成已经知道选哪项。角色名仅在顶部有唯一完整名字并经连续画面确认时记入，不覆盖手动固定名称；不显示角色名时训练比较仍可进行。角色版本、亲友、友情/羁绊、指南条等图形未可靠确认时跳过对应加分，不能声称已全部识别。

**局限：** 初次定位和变化数字仍依赖Windows已安装的中文/日文OCR组件；缺失或受系统策略限制会直接显示原因。本版不是凭空预置全字体模板，也不能保证每种客户端布局都定位成功。首次定位可能慢，不能保证实机每帧≤300ms。日期、收益和失败率缺失时不输出该项的完整比较；完整粉丝门槛/赛程仍未补齐，不能保证避免粉丝失败或达到UB。事件/心得可选择AI，使用账号额度，与本地训练通道分开。

云端检查使用人工生成画面和模拟OCR，验证“只选窗口并点一次开始→五项自动排序”、变化区域缓存、未识别数字不归零、跨回合清空和旧请求隔离；**不代表真实Windows OCR识别率或速度通过验收**。浏览器流程：`python scripts/check_automatic_panel.py`（需Playwright与Chromium）。

## v0.6：可选的自采模板通道

使用现有Pillow做轻量模板匹配，不添加OpenCV/PaddleOCR/YOLO、第三方游戏素材或大型模型。**便携包不预置客户端图像模板；仅选择这个高级模板后端时才需自行采样，默认自动模式不需要。** 附件APK未执行、未提取脚本/图片。下面v0.5的完整文字OCR保留为兼容后端，v0.7默认使用自动定位。

- 每0.1秒采样（目标10帧/秒）；对配置的相对坐标区域计算指纹，只重新匹配变化区域。页面每0.2秒刷新并合并并发轮询。模板和日期OCR分别运行，模型分析也独立；数字不需要等待日期OCR或模型即可显示，排序须等当前日期确认，避免跨回合串数据。
- 数字分割后归一化匹配自采0–9及+；数字不全、分割失败或匹配歧义则标未知。失败率建议只框数字，正收益字段保留+。无收益若显示空白，需在该收益字段采“已确认空白零收益”并填0；仅严格匹配该自采空白时记0，不将识别失败当0。
- 支持五维+收益、技能Pt、失败率、当前属性/粉丝/月份/剩余回合；训练名称、干劲、碎片颜色、学年、前后半用自采图案。日期文字可单独走后台Windows OCR，也可采学年/月份/前后半模板完全本地识别。
- 六个卡槽分别配置头像、彩圈、羁绊和提示区域。卡名来自用户标签，空槽标签为empty；有/无彩圈、满/未满羁绊、有/无!分别采yes/no。逐槽显示结果，全部槽位已知后才合计人数，未知不等于0。额外NPC、未采过的头像及新布局需要用户另行处理，不能声称已覆盖。
- 体力条按自己校准的填充/背景颜色算像素百分比，显示“约N%”，不冒充精确体力；指南条按八个格子判断。可补采不同颜色状态，陌生颜色或填充形状不一致时标未知。
- 识别结果、相似度、每槽状态和耗时可直接核对。相似度不是正确概率；画面中未确认的图标不补成已知。手动修正绑定该字段当前图像指纹，变化后失效；旧请求不能覆盖修正。

### 高级模板后端首次采样（自动模式不需要）

1. 在助手选择真实游戏窗口，确认本局角色，选“自采模板快速识别”。点击“采集样本”，助手暂停读取并抓取所选游戏窗口；截图只在本机用于框选。
2. 从自己的画面逐个采0–9和+：选择“单字模板”，框一个字并填写正确标签。也可选“数字整串”自动分字；分割个数不符时拒绝保存。自动/亮色/暗色前景可切换；相连或带装饰的字形可能需要重新圈选，不能保证所有字体都可分割。
3. 数字字形与字段选区分开：用“只设识别选区”分别圈六个完整收益字段、失败率等。选区留足变化后的位数，避开多余文字。空白的无收益字段需亲自确认并采“已确认空白零收益”，标签0；每个不同背景字段分别采。选择训练名称字段，依次切五个训练并采对应标签；五种齐后才自动判训练。
4. 学年标签用1/2/3，前后半用前半/後半；未采齐可框单独的日期文字区域使用系统OCR。干劲使用繁中标签；碎片为blue/green/pink。卡槽头像需采卡名和空槽empty，二值图标需yes/no两种。
5. 对体力/指南选择“像素条”，框条形内部并填写当前百分比或格数。中间状态可同时学到填充和背景，0/满条端点需要再补不同状态。条形颜色变化后可补样本。
6. 采完关闭窗口并开启持续读取。只需自己切换训练并保持到识别稳定，无需逐项点击读取。看完五个会给“本回合选X训练”，或按恢复/粉丝条件提出其他动作。

选区按窗口比例换算，支持同布局分辨率缩放；UI重排、长宽比/字体渲染明显变化后须重新校准。当前方法不是检测任意画面的通用视觉模型。图案模板保存在 `local-data/templates/`，只保存用户主动圈选的裁图；完整采样帧仅留内存，关闭/超时后不再使用。可在采集窗口删除采错模板。升级包不含任何本机样本，不覆盖该目录。

### 确定的本地评分

默认配置为 `guides/training_weights.json`；可在面板“评分权重配置”编辑并保存至 `local-data/training_weights.json`，立即生效，不执行配置内代码。三个阶段分别设置五维权重/目标、技能点和羁绊权重；属性上限未知为null，不编造上限。过期属性读数不用于计算剩余上限。

基本式：`分数 = (有效属性/Pt收益 + 羁绊/友情/人数/提示/指南加分) × 夏合宿系数 × (1−失败率) − 失败率×预期损失`。

有效属性收益在已知当前值及上限时截断，并按阶段目标缺口调整权重；前期羁绊更重。指南步数/满条奖励、导师未定时粉色路线倾向、古典后期粉绿倾向参考J01/J02及既有机制整理（跨服推定），具体数值权重是程序启发式。夏合宿按古典/资深年7–8月识别。体力百分比、干劲、确认可治疗异常触发休息/外出/医务室候选；与训练权重比较，按钮是否可用仍需客户端核对。粉丝门槛风险优先提醒查看比赛/报名，不凭未核验赛程断言必可参赛。

这些分数不是游戏评价分、长期期望收益的精确模拟或数学最优解。图形字段未采齐时跳过对应加分并明确列出缺项，不能说已完整考虑它们。

### 性能证据与限制

合成测试使用程序绘制的人工图案和测试字体，不是用户客户端素材。当前Linux云端对38区域、33张模板强制全匹配：中位约25ms、95分位约43ms；不变画面约6ms，重新匹配0区域。该结果**不含Windows捕获、真实游戏字体、日期OCR或用户电脑性能**，不能作为实机300ms保证。可运行 `python scripts/benchmark_templates.py` 重测；面板显示实际模板管线毫秒数，超过300ms明确提示。

真实Windows及繁中服客户端仍未验收，尤其字形分割、动态彩圈、卡槽布局、条形配色和缩放。首次日期OCR可能较慢；可自采日期组件模板或手动标定。实际养成第N回合仍需有可靠起点标定，不从日历位置猜造。所有游戏操作由用户完成；不点击、不读内存、不抓包。

## v0.5：兼容文字OCR通道

兼容后端使用Windows系统自带的中文/日文OCR，常驻进程处理局部选区，不再每个预览等待模型。没有新增大型OCR模型、Python包或运行环境下载；需要系统已安装中文/日文OCR语言组件，缺失时会明确提示。调用固定的本地PowerShell命令使用WinRT OCR，不修改执行策略，不下载外部脚本。当前Linux构建机没有Windows组件，**实际Windows OCR正确率与速度尚未验收**。识别不可靠时用“校准OCR区域”或快速录入，不把模拟测试当实机效果。

1. 点击“记录为新局”或“继续当前局”确认归属，在本地建议卡里展开“固定本局角色”，选角色版本并保存。固定名称写入本局，重启后继续当前局也保留；新局清空。支持自填角色。
2. 开启本地OCR并保存设置；选中游戏，点击“开始持续读取”。切换训练预览并保持到识别完成，会自动缓存同一回合的项目，**不需每次点读取**。本地采样每0.5秒，OCR至少间隔约0.65秒且不并发；实际每次OCR速度取决于Windows，不承诺亚秒识别。
3. 首次需要在“校准OCR区域”拖框：日期含学年/月/前后半及剩余回合；训练收益含完整六列标题和+收益；选中训练标题只圈一个项目。重复标题、看不清或不能唯一识别时拒绝猜测。只有确认选区完整并勾选后，缺少+号的列才能按0收益处理；否则未知不能补0。
4. 可分别圈选当前粉丝、目标所需粉丝、当前五维。体力只接受清晰数值，不从体力条长度估算精确值；图形干劲/友情/颜色不能可靠OCR时保留未知，允许手动补充。
5. 本地建议直接显示“已见项目中优先点哪项”、收益/风险和下一项缺失预览。未见的训练不参与比较；不保证找到全局最优。日期、资源变化或恢复会话会清空旧比较；缓存最多保留120秒。
6. 事件/心得和疑似开局、结算、放弃等不规则画面仍交模型确认，受模型限频影响。可主动点“模型分析当前画面”。本地读取不等待正在运行的模型请求；常规训练不需要模型登录和额度。

日期、剩余回合与实际养成回合分开显示。能识别“出道前剩N回合”时按该倒计时区分预览，即使没有明确日历日期；不会编造日期。仅凭日期无法保证换算为本局第N回合，因此实际回合数需用户在已知日期标定一次，之后按日期推进显示。日期或出道倒计时倒退、粉丝数异常降低会暂停建议要求确认局次。仅两次OCR一致不等于高正确率：证据明确标为“连续两次本地OCR一致”，不伪造OCR置信度。

训练排序是本程序的可解释启发式：五维收益、阶段性的技能Pt权重、前期未满羁绊人数、少量友情/在场人数加分、指南条进度和失败风险。参考J01-8/J02-5（跨服推定），**权重不是文章原公式，也不是游戏评价分公式**；未识别人数/颜色不计加分。默认超过15%失败率的训练不作为优先点击项，上限可调。缺少完整收益或失败率的预览不排序，提供快速录入替代。只读辅助不会自动点击五项训练。

## 角色目标与粉丝风险

随包提供130个角色、204个版本、376场赛事的精简参考事实，包含贵妇人/黄金巨匠。来源[R01 pretty-derby固定提交](https://github.com/wrrwrr111/pretty-derby/blob/e468b726caf1313473b82f009b9ee4f7b56475e2/public/db.json)，见 `guides/character_goals.json`，不含图片或技能事件文案。该数据的updateTime与后加入角色不一致，不用于宣称最新。

**这些是日服原生角色赛程，繁中服传奇杯适用性未核验；完整报名粉丝门槛和粉丝类目标尚未取得。** 因此不会自动当作当前剧本强制目标，也不会凭空填入门槛。请从游戏目标/报名页面识别或登记目标、期限和所需粉丝。未取得门槛或当前粉丝时明确提示不能判断安全。临近4个日期回合且粉丝不足/未知，会优先提醒先解决门槛；过期未确认的目标不会自动算作完成。已达到某个粉丝门槛也不表示其他报名条件满足。

额外赛事候选仅按登记期限、日期与所选基础角色适性筛选；继承后适性、报名资格、能否获胜、粉丝收益都需客户端确认。没有足够的已验证数据去自动计算“至少再跑几场必定够”，也不承诺杜绝粉丝失败。手动标记目标完成或删除可修正记录。

接入用户转交的三份攻略整理 J01、J02、W01，保留不同作者的策略、【有争议】和【作者经验】标记；修正聊天粘贴的转义和 Markdown 链接。整理者称已取得原文，Codex 未独立重验原文。B01 是历史 UAF 赛事资料，继续排除。

`guides/sources.json` 正式区分 `origin_server`（资料机制所属服）、`server`（目标服）和 `tw_applicability`：

| tw_applicability | 加载行为 |

| verified | 适用性已核验，可用 |
| assumed | 跨服推定、仅供参考，可用并携带醒目标记 |
| unverified、缺失或无效 | 不进入有效规则包 |

还需满足正文状态 `status=verified`、目标 `server=tw`、合法 `origin_server`（jp/tw）、`scenario=legendary`、`goal=rating` 和非空规则。当前三个有效来源**均为 assumed，没有繁中服逐条验证的结论**。模型引用这些规则时须在理由中标明来源和“跨服推定”，不能宣称“最优”或“公认”。这是提示词约束，不是建议正确性的保证。

`guide_refs` 只接受规则包里的来源 ID（J01/J02/W01），规则编号如 J01-4 写进理由；包外 ID 会导致整条建议被拒绝。`research_notes.md` 仅供人查阅，关键注意事项另放在传给模型的 `legendary_tw.md`。程序不会自动访问攻略网址更新内容。

## 整局状态与手动修正

每局独立保存以下结构化数据：导师；已持有心得（名称、蓝/绿/粉、1–3星，最多10个）及替换记录；三色指南条；距离选心得剩余回合；团队卡外出已用次数；按角色记录的亲友等级；体力及上限、干劲；已出赛比赛和名次；画面明确显示的整局出赛/胜场累计；Dream Fest 三阶段结果。

每次真实分析都会传入本局状态与最近4次观察。状态保存在 `local-data/runs.json`，重启可恢复；旧版记录自动增加未知状态，不推算历史数据。开新局清空新局资源，旧局记录保留。截图样本分析不修改真实局次。

模型可返回可选 `state_update`，字段格式为 `{value, confidence, evidence}`；API可以省略，Codex严格Schema用 `null` 表示不更新。**整体识别置信度及该字段置信度均至少0.90**才可合并。每项记录来源、证据、确认时间和回合；未看到的值不从攻略或行动建议推算，未知不是0，低置信度不会覆盖已确认值。

模型提供的心得/亲友/比赛列表视为“当前可见子集”，不会因列表没显示全就删除旧记录；明确的心得替换另行记录。重复读取同场比赛不增加场次，已知名次不会被未知名次覆盖。已记录比赛数量与整局总场次分开，漏读的比赛不会自动补成胜利。跨字段冲突、超出上限或超过10个心得会拒绝更新并提示检查。

点击“查看 / 修正本局状态”可用表单修正全部状态，查看心得替换和各项证据。打开时暂停读取；保存采用局次ID及版本检查，旧请求不能覆盖修正。保存后重新分析或手动恢复读取。删除旧心得、添加新心得后保存，会记入手动替换记录。局次未确认或处于样本模式时不能修正真实状态。

**记录是最近一次确认的观测，可能已过时。** 不会按经过的时间自动增减体力、指南条或外出次数，也不把亲友羁绊槽当等级。漏读后需展示相关页面或手动修正。无法辨认全部持有心得时，已记录列表不代表完整名单。等级数值仅做宽范围格式校验，不推断游戏中的满级数值。

## 开始使用

1. 游戏使用窗口模式，保持可见、不被其他窗口遮挡。助手中刷新窗口，选择游戏；直接点击读取会自动应用，也可点“应用配置”。
2. 列表没有游戏时用“3秒后选择前台窗口”，立即切回游戏；也可手动框选。桌面预览仅用于本机选区，之后只分析选中区域，游戏移动后需重新框选。
3. 默认“使用 ChatGPT 账号”，点击“使用 ChatGPT 登录”，在官方页面登录，再回到助手“检查登录状态”。需要可用的账号 Codex 额度，套餐、限额与组织策略以官方为准；不是直接复用当前聊天。
4. 也可自行切换视觉 API，填写地址、模型和密钥。默认 API 模型 gpt-4.1-mini，API独立计费。账号模式不会自动切换 API 计费。
5. 先手动“立即读取 / 分析”检查一回合，再启用持续读取。初次中途接入或重启后，确认“记录为新局”或“继续当前局”。状态缺失时打开相关游戏页面，或在面板修正。

本地OCR独立采样；关闭本地通道时，旧的模型自动模式仍按画面变化并稳定后分析，持续动画20秒后可尝试。账号模式自动分析至少间隔30秒，API至少8秒，实际延迟可能更长，每次仅一个请求。自动模式中的旧画面结果会丢弃；暂停不能撤回已发出的模型请求，可能仍消耗额度。更多上下文会增加请求用量。

## 局次与建议的局限

明确新养成画面创建新局；明确结算或实际放弃才结束。“是否放弃”弹窗、普通菜单不算已放弃。日期倒退、角色变化或重启恢复归属不明时暂停建议，需用户确认。手动“记录为新局”会清除旧局状态，旧请求失效；“继续当前局”保留状态。

单帧模型仍可能漏识别同角色重开，尤其跳过开局、日期又未倒退时，需要手动纠正。当前不支持后台窗口捕获、视频回放或自动遍历所有训练预览。没有看过的训练收益不可当成已知。

资料尚缺属性/技能的完整评价分、购买成本、适性修正、进化条件和可靠UB门槛；J01部分夏合宿内容未收录。跨服数值、事件时间与支援卡差异未逐条核验，杏目条件仍有争议。更多记录和攻略不等于完整游戏模拟器。

## 数据与组件

只有选择的游戏截图及状态/攻略上下文发送给所选模型服务，不录像。API密钥仅在内存，不写本地记录。ChatGPT 登录由官方 Codex 管理，本程序不读取或复制 OAuth 凭据，也不要求在聊天中提交凭据。

Codex 固定版本0.159.2，使用官方图片输入、JSON Schema、临时会话和只读沙箱，禁用命令/浏览器/电脑操作等工具。安装验证固定SHA512，构建验证npm官方签名；来源见 `umacoach/codex_provenance.json` 和[官方账号使用说明](https://github.com/openai/codex#using-codex-with-your-chatgpt-plan)。

Codex分析截图临时保存在 `local-data/codex-tmp`，结束后删除，强制退出可能残留。局次、结构化状态及识别文字保存在 `local-data`，已被Git忽略；退出后可自行备份或删除。便携运行环境来自PSF NuGet，验证SHA512和CMS证书链；Pillow验证PyPI SHA256，许可证与来源随包保留。不修改系统PATH。
