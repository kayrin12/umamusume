# 赛马娘繁中服 · 养成助手 v0.4.1

Windows 10/11 64位只读辅助：读取可见游戏画面，通过 ChatGPT 账号（官方 Codex）或视觉 API 提供下一步建议，独立记录每次养成。不自动点击、不读游戏内存、不修改游戏文件。

**这是可测试原型。攻略含跨服推定和作者经验，缺少完整评分模型；不保证每回合最优或达到 UB。** 用户已确认旧版可捕获窗口；v0.4 的真实 Windows、游戏识别和账号分析仍需本机验收。

## v0.4 的改动

接入用户转交的三份攻略整理 J01、J02、W01，保留不同作者的策略、【有争议】和【作者经验】标记；修正聊天粘贴的转义和 Markdown 链接。整理者称已取得原文，Codex 未独立重验原文。B01 是历史 UAF 赛事资料，继续排除。

`guides/sources.json` 正式区分 `origin_server`（资料机制所属服）、`server`（目标服）和 `tw_applicability`：

| tw_applicability | 加载行为 |
| --- | --- |
| verified | 适用性已核验，可用 |
| assumed | 跨服推定、仅供参考，可用并携带醒目标记 |
| unverified、缺失或无效 | 不进入有效规则包 |

还需满足正文状态 `status=verified`、目标 `server=tw`、合法 `origin_server`（jp/tw）、`scenario=legendary`、`goal=rating` 和非空规则。当前三个有效来源**均为 assumed，没有繁中服逐条验证的结论**。模型引用这些规则时须在理由中标明来源和“跨服推定”，不能宣称“最优”或“公认”。这是提示词约束，不是建议正确性的保证。

`guide_refs` 只接受规则包里的来源 ID（J01/J02/W01），规则编号如 J01-4 写进理由；包外 ID 会导致整条建议被拒绝。`research_notes.md` 仅供人查阅，关键注意事项另放在传给模型的 `legendary_tw.md`。程序不会自动访问攻略网址更新内容。

## 整局状态与手动修正

每局独立保存以下结构化数据：导师；已持有心得（名称、蓝/绿/粉、1–3星，最多10个）及替换记录；三色指南条；距离选心得剩余回合；团队卡外出已用次数；按角色记录的亲友等级；体力及上限、干劲；已出赛比赛和名次；画面明确显示的整局出赛/胜场累计；Dream Fest 三阶段结果。

每次真实分析都会传入本局状态与最近4次观察。状态保存在 `local-data/runs.json`，重启可恢复；旧版记录自动增加未知状态，不推算历史数据。开新局清空新局资源，旧局记录保留。截图样本分析不修改真实局次。

模型可返回可选 `state_update`，字段格式为 `{value, confidence, evidence}`；API可以省略，Codex严格Schema用 `null` 表示不更新。**整体识别置信度及该字段置信度均至少0.90**才可合并。每项记录来源、证据、确认时间和回合；未看到的值不从攻略或行动建议推算，未知不是0，低置信度不会覆盖已确认值。

模型提供的心得/亲友/比赛列表视为“当前可见子集”，不会因列表没显示全就删除旧记录；明确的心得替换另行记录。重复读取同场比赛不增加场次，已知名次不会被未知名次覆盖。已记录比赛数量与整局总场次分开，漏读的比赛不会自动补成胜利。跨字段冲突、超出上限或超过10个心得会拒绝更新并提示检查。

点击“查看 / 修正本局状态”可用表单修正全部状态，查看心得替换和各项证据。打开时暂停读取；保存采用局次ID及版本检查，旧请求不能覆盖修正。保存后重新分析或手动恢复读取。删除旧心得、添加新心得后保存，会记入手动替换记录。局次未确认或处于样本模式时不能修正真实状态。

**记录是最近一次确认的观测，可能已过时。** 不会按经过的时间自动增减体力、指南条或外出次数，也不把亲友羁绊槽当等级。漏读后需展示相关页面或手动修正。无法辨认全部持有心得时，已记录列表不代表完整名单。等级数值仅做宽范围格式校验，不推断游戏中的满级数值。

## 开始使用

1. 游戏使用窗口模式，保持可见、不被其他窗口遮挡。助手中刷新窗口，选择游戏；直接点击读取会自动应用，也可点“应用配置”。
2. 列表没有游戏时用“3秒后选择前台窗口”，立即切回游戏；也可手动框选。桌面预览仅用于本机选区，之后只分析选中区域，游戏移动后需重新框选。
3. 默认“使用 ChatGPT 账号”，点击“使用 ChatGPT 登录”，在官方页面登录，再回到助手“检查登录状态”。需要可用的账号 Codex 额度，套餐、限额与组织策略以官方为准；不是直接复用当前聊天。
4. 也可自行切换视觉 API，填写地址、模型和密钥。默认 API 模型 gpt-4.1-mini，API独立计费。账号模式不会自动切换 API 计费。
5. 先手动“立即读取 / 分析”检查一回合，再启用持续读取。初次中途接入或重启后，确认“记录为新局”或“继续当前局”。状态缺失时打开相关游戏页面，或在面板修正。

每秒本地采样，画面变化并稳定后才分析；持续动画时20秒后可尝试。账号模式自动分析至少间隔30秒，API至少8秒，实际延迟可能更长，每次仅一个请求。自动模式中的旧画面结果会丢弃；暂停不能撤回已发出的模型请求，可能仍消耗额度。更多上下文会增加请求用量。

## 局次与建议的局限

明确新养成画面创建新局；明确结算或实际放弃才结束。“是否放弃”弹窗、普通菜单不算已放弃。日期倒退、角色变化或重启恢复归属不明时暂停建议，需用户确认。手动“记录为新局”会清除旧局状态，旧请求失效；“继续当前局”保留状态。

单帧模型仍可能漏识别同角色重开，尤其跳过开局、日期又未倒退时，需要手动纠正。当前不支持后台窗口捕获、视频回放或自动遍历所有训练预览。没有看过的训练收益不可当成已知。

资料尚缺属性/技能的完整评价分、购买成本、适性修正、进化条件和可靠UB门槛；J01部分夏合宿内容未收录。跨服数值、事件时间与支援卡差异未逐条核验，杏目条件仍有争议。更多记录和攻略不等于完整游戏模拟器。

## 数据与组件

只有选择的游戏截图及状态/攻略上下文发送给所选模型服务，不录像。API密钥仅在内存，不写本地记录。ChatGPT 登录由官方 Codex 管理，本程序不读取或复制 OAuth 凭据，也不要求在聊天中提交凭据。

Codex 固定版本0.159.2，使用官方图片输入、JSON Schema、临时会话和只读沙箱，禁用命令/浏览器/电脑操作等工具。安装验证固定SHA512，构建验证npm官方签名；来源见 `umacoach/codex_provenance.json` 和[官方账号使用说明](https://github.com/openai/codex#using-codex-with-your-chatgpt-plan)。

Codex分析截图临时保存在 `local-data/codex-tmp`，结束后删除，强制退出可能残留。局次、结构化状态及识别文字保存在 `local-data`，已被Git忽略；退出后可自行备份或删除。便携运行环境来自PSF NuGet，验证SHA512和CMS证书链；Pillow验证PyPI SHA256，许可证与来源随包保留。不修改系统PATH。

本次云端验证：89项自动测试通过；真实Chromium已检查全部状态表单、替换记录、模型状态合并、版本冲突和新局清空，未出现JavaScript错误。Codex结构化输出Schema也通过JSON Schema验证。浏览器检查中的截图及模型返回是模拟数据，没有消费用户账号额度。
