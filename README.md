# 赛马娘繁中服 · 实时养成助手原型

Windows 原生客户端的只读辅助：持续读取**可见的游戏窗口区域**，在画面变化并稳定后发送截图给视觉模型，显示下一步建议并记录每次养成（run）。不会自动点击、读取游戏内存或修改游戏文件。

**当前阶段是可测试原型，尚未在真实 Windows 游戏客户端验收，也未接入已核验的现行传奇杯攻略。不能保证“每回合最优”或达到 UB。**

## Windows 便携版（无需安装 Python）

[从 GitHub 下载 v0.3 便携包](https://github.com/kayrin12/umamusume/raw/refs/heads/codex/portable-delivery/downloads/umacoach-windows-portable-x64-v0.3.0.zip)，完整解压后进入 `umacoach` 文件夹，双击 `start.bat`。适用于 Windows 10/11 64位，自带 Python 3.13.16 和 Pillow 12.3.0；打开预览无需安装 Python 或 Node.js，也不修改系统 PATH。

**聊天里的界面预览无法读取你电脑的窗口。必须先下载完整 ZIP，在自己的 Windows 电脑上运行 `start.bat`。不要直接打开仓库中的 `panel.html`。** 启动窗口会输出本次运行的本机面板地址，浏览器未自动打开时可复制该地址打开。

程序会打开本机浏览器面板，保留命令窗口。选中游戏窗口并“应用配置”后即可本地预览。v0.3 默认使用 ChatGPT 账号分析，通过官方 Codex 登录，不必填写 API Key。退出请点“退出助手”或关闭命令窗口，仅关闭网页不会停止后台。

### 使用现有 ChatGPT 账号获取建议（v0.3）

1. 分析方式保持“使用 ChatGPT 账号”，点击“使用 ChatGPT 登录”。
2. 首次会自动下载约162MB的官方 Codex Windows 组件，解压约449MB；后续复用。下载核对固定 SHA512；构建时已验证该固定版本的 npm 官方 ECDSA 签名，元数据见 `umacoach/codex_provenance.json`。组件安装在本程序 `.runtime/codex` 中，不需要管理员权限。
3. 在官方 Codex 打开的页面中登录你自己的 ChatGPT 账号，然后回到助手点击“检查登录状态”。本程序不读取或复制 OAuth 令牌，也不会让你在聊天里提交凭据。
4. 显示已登录后，点“立即读取 / 分析”。ChatGPT模式使用账号的 Codex 额度和频率限制，具体可用性取决于套餐、组织策略及官方服务；没有无限使用承诺。它不能直接复用此云端聊天会话。
5. 自动分析至少间隔30秒，实际分析可能更慢；建议先手动验证一回合，再启用持续读取。达到额度限制会暂停，不会切换到 API 计费。

官方依据：[Codex CLI README 的 Using Codex with your ChatGPT plan](https://github.com/openai/codex#using-codex-with-your-chatgpt-plan)。固定 CLI 版本为0.159.2，使用官方图片输入、JSON Schema输出、临时会话与只读沙箱；分析进程禁用命令、浏览器、电脑操作及多代理工具。ChatGPT登录凭据由官方CLI自行管理。尚未在用户 Windows 账号上完成真实登录和模型验收，不能把模拟测试当作账号可用性证明。

也可切换到“使用视觉 API 密钥”，按服务要求填写地址、模型与密钥，API单独计费。两种方式不会自动混用。

### 窗口列表里没有游戏（v0.2）

先退出旧助手，再完整解压新版并启动，页面顶部应显示“v0.3 ChatGPT 账号模式”。

1. 点击“3秒后选择前台窗口”，立即切回游戏并等待3秒。助手会取得当时的前台窗口，成功后直接显示预览，不依赖游戏标题或列表成员。
2. 也可点“手动框选游戏画面”：桌面截图只在本机显示供框选，拖动框出完整游戏区域并确认。只有确认的区域会被后续读取和分析，整张桌面截图不会发送给视觉 API。游戏需保持可见，移动或缩放后重新框选。
3. 点“开始持续读取”。未登录也能预览；完成 ChatGPT 登录或配置 API 后，所选区域才能得到模型建议。

窗口枚举现保留可见的无标题窗口，以窗口类型名代替标题，并显式声明64位 Win32 函数参数与返回值。仍无法选择时，可点“查看读取诊断”，记录平台、版本、位数、窗口数量与采集错误；诊断不包含密钥或屏幕内容。

### 点按钮出现 XML / Unexpected token

这表示响应内容不是助手接口的 JSON，不能据此判断游戏捕获失败。v0.2.1 会在允许操作前校验页面来源、本机服务标记与本次进程身份；静态界面文件和聊天预览会停用操作并提示运行 `start.bat`。非 JSON 响应会显示状态和格式，不再直接抛出 JSON 解析错误。程序启动时也会绕过环境代理探测自己的本机服务，再打开面板；不会修改系统或浏览器代理设置。

运行环境来自 Python Software Foundation 的官方 NuGet `python` 包，已核对 NuGet 官方目录 SHA512 和 CMS 签名证书链；Pillow Windows wheel 已核对 PyPI SHA256。原有许可证随包保留，来源及校验值见包内 `.runtime/provenance.json`。

开发者可用 `python scripts/build_portable.py` 重建便携包；构建需要 OpenSSL 和访问 NuGet/PyPI，校验失败会终止。Windows 二进制不能在当前 Linux 构建机直接执行，真实 Windows 启动和捕获仍待验收。

## Windows 源码版（开发用）

1. 安装官方 Python 3.11 或更新版本，保留 Tcl/Tk 和 Python Launcher。
2. 下载并解压本项目，双击 `start.bat`。首次会创建 `.venv` 并安装 Pillow；需要联网下载依赖。
3. 启动繁中服游戏，使用窗口模式，确保画面可见、未被其他窗口遮挡。助手可放在旁边或另一块屏幕上；置顶面板不要挡住游戏。
4. 助手中点击“刷新窗口”，按标题选中真实游戏窗口。多个同名窗口可根据显示的窗口句柄区分。
5. 配置支持图片输入及 JSON 输出的 OpenAI 兼容 Chat Completions API。默认根地址为 `https://api.openai.com/v1`，模型 `gpt-4.1-mini`；可改为服务实际提供的视觉模型。密钥仅留在进程内存，关闭即丢弃，也可通过本机环境变量 `UMACOACH_API_KEY` 注入。不要把密钥发到聊天或提交进 Git。
6. 点击“开始持续读取”。每秒本地采样；画面稳定、相较上次成功分析有显著变化且距离上次分析至少 8 秒时发起分析。持续动画导致画面无法稳定时，变化等待 20 秒后也会尝试分析。每次只允许一个请求，API 超时 50 秒；实际延迟取决于网络和模型。即使未操作，游戏动画也可能触发付费请求。
7. 需要立即分析时点按钮或在助手窗口有焦点时按 **F8**（不是全局热键）。可暂停自动模式。

只有所选窗口/区域的截图会发给选用的模型服务。不录像；Codex模式将待分析截图临时写入 `local-data/codex-tmp`，分析结束后删除，强制终止进程时可能残留。退出后可以清理该目录。局次和识别文字也保存在 `local-data/`，目录已被 Git 忽略。截图导入模式不改变真实局次。

### 每局的开始与结束

- 明确的新养成开始画面：创建独立 run ID，清除旧局上下文。
- 明确的养成结算／已完成放弃画面：结束本局。
- “是否放弃”确认弹窗：仅记录待确认，不提前结束。
- 发现日期倒退或角色变化：暂停建议，提示确认是否重开；不会直接把画面并入旧局。
- 中途打开助手或重新启动助手：需要点“记录为新局”或“继续当前局”确认归属。未确认前不输出养成操作建议。
- 自动识别漏掉放弃或开局时，用“本局已放弃”“记录为新局”纠正。正在请求的旧局结果会被丢弃；手动确认后需重新分析。

边界检测目前依赖单帧视觉模型与日期/角色的一致性检查，不能保证全自动准确。若同角色重开、又跳过开局且新画面日期不倒退，单凭采样截图可能无法区分两局，必须手动纠正。当前不包含视频回放或后台窗口采集。

### 推荐的依据与限制

默认 `guides/legendary_tw.md` 仅记录用户已知成绩与待核验来源，**没有已核验且适用于当前传奇杯冲分的主流攻略规则**。已读取用户提供的 B 站文章，但它是 2025 年 9 月发布的 UAF 版本历史赛事攻略。另两篇 miturunn-pocketbook.com 和 note.com 文章被代理以 403 拦截，域名已补入环境配置草稿，正文仍未取得。详见 `guides/research_notes.md`。

`guides/sources.json` 记录来源、读取状态、服务器、剧本和目标。运行时只有 `verified`、`tw`、`legendary`、`rating` 且包含非空 `rules` 的资料才会进入规则包；历史赛事、日服待确认资料和未读取正文均被排除。模型若引用不在有效规则包中的攻略ID，整条建议会被拒绝。接入资料时应先补充来源、日期、版本及具体证据，再更改核验状态；不要只更改状态来消除警告。

用户指定优先参考作者“年酱775”；已读 B 站文章作者为冬木鸭/六老师，不能混同。目前仍未确认属于“年酱775”的具体作品。

一个训练页通常只显示当前选中项目的具体收益；未预览所有项目时，助手不能知道其他项目的真实数值。它会提示查看缺失预览，最近四次已识别画面作为本局短期上下文。API 返回的建议来自模型推理，不是完整游戏模拟器的最优解。

## 开发与验证

本任务使用现有隔离 checkout，不需要创建额外 worktree。

```sh
cd /workspace/umamusume
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m umacoach.app
```

Linux 可运行核心测试；图形界面需要桌面显示服务。实时捕获只支持 Windows。测试覆盖放弃重开、日期回退、角色变化、重复开局、重启恢复、低置信度、限频、视觉请求结构等；模拟 API 测试不代表真实视觉识别通过。

Windows 手工验收还需：真实官方 ChatGPT 登录及账号额度、真实开局→训练→放弃→重开→结算、模型读取繁中 UI 和实战建议质量。API模式需自己的密钥；交接包中只有角色详情、技能与结算截图。

本次云端验证：59 项测试通过，新增覆盖 ChatGPT/API认证区分、账号模式禁用API兜底、图片与JSON Schema参数、只读工具限制、临时截图清理、组件校验失败拦截和账号建议流程。CLI及模型结果使用模拟进程验证，未在此任务中消费用户账号的模型额度。图形界面使用真实Chromium进行本地操作检查，Windows采集与认证使用模拟数据。

旧 Tk 界面曾通过模拟异步响应的流程检查，但云端 Tk 的中文字体渲染异常；便携版采用浏览器面板。未调用真实视觉 API，未执行 Windows 运行环境或真实游戏捕获，仍需 Windows 验收。
